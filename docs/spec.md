# Sustain VS Code extension: build specification

- Status: Accepted, 2026-10-10 (from the design interview with the owner)
- Reference implementation: `reference/sustain-prototype/` (Rust "ArchAlign"). It is **read-only** reference material: nothing is imported from it, and the root `.gitignore` excludes it. Files needed from it are copied (vendored) into this repo as listed in §6.
- Progress: `docs/progress.md` · Structure: `docs/architecture.md` · Decisions: `docs/adr/` (MADR 4.0). All three are created in M0 and maintained throughout (§9).

This document is the contract for a long-running, mostly autonomous implementation. Requirements have stable IDs, acceptance criteria (AC) and a verification tag. The implementer follows §9 (process) and §10 (deviation policy).

Verification tags:

| Tag | How it's verified |
|---|---|
| `[unit]` | vitest test in Node |
| `[dom]` | vitest test in a `happy-dom` environment (webview code) |
| `[e2e]` | `@vscode/test-electron` test running inside a downloaded VS Code |
| `[live]` | Real Claude Code / Codex run, recorded in `progress.md` |
| `[manual]` | Checked by hand by the owner in an Extension Development Host |

## 1. Purpose

Sustain is a VS Code extension that shows a repository's architecture as a diagram and opens the code behind each diagram node. The diagram is generated by an **external coding agent** (Claude Code or Codex) following a skill that ships with the extension. The extension never calls an LLM.

Diagrams use the Archify JSON v1 format (`schema_version: 1`, `diagram_type: "architecture"`), the same format the prototype reads and writes. Archify is MIT-licensed (github.com/tt-a1i/archify); Sustain is not affiliated with it.

## 2. Goals

| ID | Goal |
|---|---|
| G1 | Architecture viewer: render an Archify diagram from `.archify/*/candidate.json` in a VS Code webview panel. |
| G2 | Clicking a diagram node opens the cited code file at the cited lines in a VS Code editor. |
| G3 | One agent skill, `sustain-architecture`, lets Claude Code or Codex analyse the codebase and produce a validated diagram. |
| G4 | The extension installs the skill into the workspace and can launch the agent in an integrated terminal. |

## 3. Non-goals

- Any LLM call, API key, provider setting, budget or consent flow inside the extension.
- Tree pane, built-in source viewer, citation badges, Problems list, upstream/downstream reach, node finder, history browser, Re-layout, cards, legend, guided views, icons, brand marks, exports, editing diagrams.
- Validation of a diagram when the viewer opens it (only the agent-side validator validates).
- Detecting lines that moved but are still in range (no content hashes in Archify v1).
- A `sustain-architecture-refresh` skill. Re-run the skill instead.
- Agents other than Claude Code and Codex; skill directories other than `.claude/skills` and `.agents/skills`.
- VS Code for the Web, remote-only or virtual workspaces. Marketplace publishing (install from `.vsix`).
- Editing `.gitignore` in user repositories.
- Run logs (`run.jsonl`), turn/token budgets.

## 4. Glossary

| Term | Meaning |
|---|---|
| Repo root | For a diagram at `<R>/.archify/<run>/candidate.json`, the folder `<R>`. Every `sources[].path` is relative to it. |
| Run folder | `.archify/architecture-<slug>-<YYYYMMDD-HHMMSS>[-N]/` |
| Draft | `<run folder>/draft.json`, written by the agent, not yet accepted |
| Candidate | `<run folder>/candidate.json`, a draft the validator accepted |
| Source / citation | One entry of `components[].sources[]`: `{path, line?, end_line?, label?}` |
| App-owned fields | Fields the validator sets or removes; the agent must not author them (FR-VAL-02) |

## 5. Decision record

These were settled with the owner. Changing any of them needs owner approval (§10). In M0 each row (or tightly related group of rows) becomes an accepted ADR (FR-DOC-03); afterwards the ADRs are authoritative and this table is their summary.

| Topic | Decision |
|---|---|
| Agent runtime | External coding agent driven by a skill. No agent loop in the extension. |
| Target agents | Claude Code (`.claude/skills/`), Codex (`.agents/skills/`) |
| Skill set | One skill, `sustain-architecture`, with bundled `repo-facts.mjs` and `validate.mjs` |
| Invocation | Manual only: Claude `disable-model-invocation: true`; Codex `policy.allow_implicit_invocation: false` |
| Claude pre-approvals | `allowed-tools: Read Grep Glob Bash(node .agents/skills/sustain-architecture/scripts/*)`; writes still prompt |
| Install layout | Real files in `.agents/skills/sustain-architecture/`; `.claude/skills/sustain-architecture` is a relative symlink to it, copy on symlink failure |
| Validator runtime | Dependency-free `.mjs` bundles built from the extension's TypeScript, Node ≥ 18 |
| Publish rule | Validator moves `draft.json` → `candidate.json` on success; failed runs keep `draft.json` |
| App-owned fields | Validator strips agent-authored geometry/presentation fields with a warning, and sets `meta.repository`/`meta.output` itself |
| Layout | elkjs in the webview; authored `pos`/`size` used when every component has them |
| Viewer host | WebviewPanel in an editor column; code opens in the other column |
| Viewer validation | None on load; tolerant parsing (FR-VIEW-03); stale citations reported on click |
| Data | Archify JSON v1 and the `.archify/` folder layout, unchanged from the prototype |
| Platform | Desktop VS Code, `.vsix` install, user picks one folder in multi-root workspaces |
| Tooling | TypeScript, npm, esbuild, vitest; webview is plain TypeScript rendering SVG, no framework |

## 7. Requirements

### 7.1 Project and quality (NFR)

**NFR-QUAL-01 Gates.** `npm run check` runs `tsc --noEmit` (strict), `vitest run`, `npm run check:docs` (FR-DOC-03) and `npm run build`. `npm run test:e2e` runs the `[e2e]` suite. AC: both exit 0 at the end of every milestone. `[unit]`

**NFR-QUAL-02 Dependencies.** Runtime: `elkjs`, `ajv` (bundled, never `require`d at runtime from `node_modules`). Dev: `typescript`, `esbuild`, `vitest`, `happy-dom`, `@types/vscode`, `@types/node`, `@vscode/test-electron`, `mocha` (e2e runner only), `@vscode/vsce`. Exact versions pinned in `package.json`. A new runtime dependency needs an ADR (FR-DOC-03) before it is added; a new dev dependency needs a one-line justification in `docs/progress.md`. AC: `package.json` matches this list plus justified additions. `[manual]`

**NFR-QUAL-03 Boundaries.** `src/model/` and `src/layout/` import neither `vscode` nor Node built-ins other than through injected interfaces where noted (`citations.ts`, `git.ts`, `runFolder.ts` and `discovery.ts` may use `node:fs`/`node:path`/`node:child_process`; `layout` and `tolerant` must be browser-safe). AC: a unit test scans imports of `src/layout/**` and `src/model/{types,tolerant,checks}.ts` and fails on `vscode` or `node:` imports. `[unit]`

**NFR-SEC-01 Webview.** Strict CSP: `default-src 'none'`; scripts only via nonce from `dist/webview.js`; styles from `dist/webview.css` and `${webview.cspSource}`; no `unsafe-eval`, no remote resources. `localResourceRoots` is `dist/` only. The webview never receives file contents, only the diagram JSON. AC: CSP string asserted in a unit test of the HTML builder; elkjs works under it (`[manual]` check in M3). `[unit]`

**NFR-SEC-02 No network.** Neither the extension nor the scripts make network requests. AC: a unit test scans `src/**` and fails on imports of `http`, `https`, `net`, `tls`, `dgram` (with or without `node:`) and on `fetch(`, `XMLHttpRequest` or `WebSocket` usage. `[unit]`

**NFR-PERF-01 Layout.** Laying out a 60-component, 120-connection diagram with 2 levels of boundaries takes < 1 s in Node. AC: timing test, median of 5. `[unit]`

### 7.2 Shared model (`src/model/`)

**FR-MOD-01 Types.** TypeScript types for the Archify v1 subset Sustain reads: root, `meta`, `components`, `connections`, `boundaries`, `layout` (grid), `sources`. Unknown fields are preserved when a document is rewritten by the validator. AC: every fixture round-trips through parse → stringify as an equal JSON value. `[unit]`

**FR-MOD-02 Schema.** `schema.ts` compiles both vendored schemas with Ajv's draft 2020-12 build (`ajv/dist/2020`), `allErrors: true`, `strict: false`, `$ref`s resolved by `$id` from the two local files only. Errors map to `{pointer, message}` where `pointer` is the JSON pointer of the failing instance location (for `additionalProperties`, the pointer of the extra property). AC: all 24 fixtures pass; a fixture with `components[1].type = "nope"` reports pointer `/components/1/type`; an extra field `colour` reports `/components/0/colour`. `[unit]`

### 7.3 Validator (`validate.mjs`)

Port of the prototype's Submission profile (`archalign-model/src/{submission,checks,citations}.rs`, `archalign-agent/src/gate.rs`, `archalign-repo/src/{deny,text}.rs`).

**FR-VAL-01 CLI.** `node <skill>/scripts/validate.mjs <path-to-draft.json>`. The path must be `<R>/.archify/<run>/draft.json` (absolute or relative to cwd); `<R>` is the repo root. Output: exactly one JSON object on stdout:

```json
{
  "status": "accepted" | "rejected",
  "candidate": ".archify/<run>/candidate.json",
  "errors":   [{ "pointer": "/components/3/sources/0/end_line", "message": "..." }],
  "warnings": [{ "pointer": "/components/0/pos", "message": "Removed app-owned field" }],
  "hint": "Fix exactly these errors and run the validator again."
}
```

`candidate` only when accepted; `hint` only when rejected. At most 50 errors are listed; if more, a final entry `{pointer: "", message: "N more errors not shown"}`. Exit code 0 accepted, 1 rejected, 2 usage or I/O error (message on stderr, no stdout JSON). AC: unit tests for each exit path, run against the built `.mjs` with `node` as a child process. `[unit]`

**FR-VAL-02 Step 1: app-owned fields.** Before any check, on the parsed JSON value:

- Remove, each reported as a warning with its pointer: root `layout`; `meta.{viewBox, views, animation, translations, visual_preset, engineering_profile}`; `components[].{pos, size, row, col, icon, brand}`; `connections[].{fromSide, toSide, route, via, labelAt, labelDx, labelDy, labelSegment, width}`; `boundaries[].pad`.
- Set `schema_version: 1`, `diagram_type: "architecture"`, `meta.locale: "en"`, `meta.quality_profile: "showcase"`, `meta.output: ".archify/<run>/<slug>.html"` (`<slug>` parsed from the run folder name; the file is never written).
- Set `meta.repository` from FR-GIT-01 when available; otherwise remove any agent-supplied `meta.repository` with a warning.

Removals are not rejections. AC: a draft with every removable field set is accepted (if otherwise valid) and the candidate contains none of them; warnings list every pointer. `[unit]`

**FR-VAL-03 Step 2: schema.** FR-MOD-02 on the step-1 result. Any error rejects.

**FR-VAL-04 Step 3: semantic checks** (all errors), ported from `checks.rs`:

- Duplicate component `id` → `/components/i/id`; duplicate connection `id` → `/connections/i/id`.
- Connection `from`/`to` naming an unknown component → `/connections/i/from|to`; boundary `wraps` naming an unknown component → `/boundaries/i/wraps/j`.
- Component without sources → `/components/i` (`MissingSources`).
- Two boundaries with partially overlapping or equal member sets → `/boundaries/j`.

AC: one unit test per rule, asserting the pointer. `[unit]`

**FR-VAL-05 Step 4: citations.** For each `components[i].sources[k]` (pointer `/components/i/sources/k[/field]`):

- Path syntax: non-empty, ≤ 240 chars, `/` separators only (no `\`), not absolute, no empty, `.` or `..` segments → `InvalidCitationPath`.
- Deny-list (port of `deny.rs`, case-insensitive, any segment): `.git`, `.archify`, `.npmrc`, `.pypirc`, `.netrc`, `.env` and `.env.*` except `.env.example`/`.env.sample`, names starting `id_rsa`/`id_ed25519`, extensions `pem`, `key`, `p12`, `pfx` → `DeniedCitation`.
- Resolution: the real path (symlinks resolved) must stay inside the repo root's real path; must exist; must be a regular file; ≤ 2 MiB; no NUL byte in the first 8 KiB → otherwise `BrokenCitation` naming the reason.
- Lines: line count = number of `\n`-separated lines, a trailing newline not counting as an extra line. `line ≥ 1`, `line ≤ count`; `end_line` requires `line`, `end_line ≥ line`, `end_line ≤ count` → otherwise `BrokenCitation` with the file's line count in the message.

AC: a temp repo fixture exercising every rule, including a symlink pointing outside the root. `[unit]`

**FR-VAL-06 Publish.** Steps run in order; schema errors stop before steps 3–4 (they need a typed document). If every step passes, write the step-1 result to `candidate.json` (2-space JSON, trailing newline) via temp file + rename, then delete `draft.json`. If rejected, `draft.json` is left untouched and no `candidate.json` is written. AC: accepted run leaves only `candidate.json`; rejected run leaves only `draft.json` byte-identical. `[unit]`

### 7.4 Repo facts (`repo-facts.mjs`)

**FR-GIT-01 Git facts.** Run `git` with a fixed argv, `GIT_TERMINAL_PROMPT=0`, stdin closed, from the repo root. Collected only when the repo root is the work tree top level and HEAD exists: HEAD (40-hex), origin URL with HTTP(S) userinfo stripped (port of `sanitize_origin`), dirty paths (≤ 200, plus total count). `meta.repository` = `{url, revision}` plus `provider: "github"|"gitee"` for HTTPS hosts `github.com`/`gitee.com`, otherwise `link_mode: "local-only"`; absent when there is no origin. Git missing, not a repo, or a subfolder of a work tree → no git facts, no error. AC: unit tests with temp git repos (clean, dirty, no origin, origin with credentials, subfolder) and with `git` absent from PATH. `[unit]`

**FR-RF-01 CLI.** `node <skill>/scripts/repo-facts.mjs [--focus <text>]`, run with cwd = repo root. It creates the run folder and prints one JSON object:

```json
{
  "root": "/abs/path",
  "runFolder": ".archify/architecture-<slug>-<YYYYMMDD-HHMMSS>",
  "draft": ".archify/architecture-<slug>-<YYYYMMDD-HHMMSS>/draft.json",
  "git": { "head": "<40-hex>", "origin": "https://...", "dirtyCount": 3, "dirty": ["src/a.ts"] } | null
}
```

Slug: port of `slugify` (lowercase `[a-z0-9-]` kebab-case of the focus, else of the repo folder name, else `repo`; ≤ 40 chars cut at a word boundary). Timestamp: local time. Name collision → append `-2`, `-3`, …. Exit 0 on success, 2 on error. AC: slug table test ported from the prototype's storage tests; collision test. `[unit]`

### 7.5 Skill (`skills/sustain-architecture/`)

**FR-SKL-01 Frontmatter.** `SKILL.md`:

```yaml
---
name: sustain-architecture
description: Generate an Archify architecture diagram of this repository for the Sustain VS Code viewer. Invoke manually with an optional focus.
disable-model-invocation: true
allowed-tools: Read Grep Glob Bash(node .agents/skills/sustain-architecture/scripts/*)
---
```

`agents/openai.yaml`:

```yaml
interface:
  display_name: "Sustain Architecture"
  short_description: "Generate an architecture diagram for Sustain"
policy:
  allow_implicit_invocation: false
```

AC: unit test parses both files and asserts these fields. Codex accepting the Claude-only frontmatter key is verified in FR-LIVE-02. `[unit]`

**FR-SKL-02 Body.** Imperative steps, every script referenced by repo-root path:

1. Focus: Claude Code substitutes `$ARGUMENTS`; in Codex the focus is the text after the skill mention. Empty means a whole-system overview.
2. From the repo root run `node .agents/skills/sustain-architecture/scripts/repo-facts.mjs --focus "<focus>"` (omit `--focus` when empty). Use `runFolder`, `draft` and `git` from its output.
3. Read `references/archify-format.md`. Use `references/example.json` as a shape example only.
4. Explore with the agent's own read/search tools, following the order in archify-format.md. Never open or cite deny-listed paths (list them).
5. Write the complete diagram to the `draft` path. Write nothing else anywhere.
6. Run `node .agents/skills/sustain-architecture/scripts/validate.mjs <draft>`. On `rejected`, fix exactly the listed pointers, rewrite the whole draft, re-run. At most 3 repairs (4 validator runs); after the 4th rejection stop and report the remaining errors and the draft path.
7. On `accepted`, report the candidate path and component count, and say the Sustain viewer will offer to open it.

AC: `[live]` runs (FR-LIVE-*) follow these steps without extra user instruction.

**FR-SKL-03 Format reference.** `references/archify-format.md` is adapted from the prototype's `crates/archalign-agent/prompts/system.md`: keep "How you work" ordering (map the slice, trace ownership, record evidence, name uncertainty, stop), Composition and Schema rules; remove every mention of the prototype's tools (`list_dir`, `read_file`, `grep`, `repo_meta`, `submit_diagram`) and of "the app"; describe validation as the `validate.mjs` steps of FR-VAL-02…05; keep the Archify attribution line. AC: unit test asserts none of those five tool names appear. `[unit]`

### 7.6 Install and generate commands

**FR-WS-01 Folder choice.** Every command that needs a repo root uses the single workspace folder, or a QuickPick of folders when there are several. No folder open → error notification "Open a folder first." `[e2e]`

**FR-INS-01 `Sustain: Install Agent Skills`** (`sustain.installSkills`).

- Copy `dist/skills/sustain-architecture/**` to `<root>/.agents/skills/sustain-architecture/`.
- Create `<root>/.claude/skills/sustain-architecture` as a relative directory symlink `../../.agents/skills/sustain-architecture` (`'junction'` type on Windows). If symlink creation throws, copy the files instead.
- If either target exists, a modal asks "Overwrite the existing sustain-architecture skill?" (Overwrite / Cancel). Overwrite removes both targets first. Cancel changes nothing.
- Success → info notification naming both paths.

AC: `[e2e]` fresh install creates both, the `.claude` entry is a symlink; overwrite path; cancel path. `[e2e]`

**FR-GEN-01 `Sustain: Generate Architecture`** (`sustain.generateArchitecture`).

1. Folder choice (FR-WS-01).
2. If `<root>/.agents/skills/sustain-architecture/SKILL.md` is missing, ask "Install the sustain-architecture skill first?" (Install / Cancel) and run FR-INS-01.
3. InputBox "Focus (optional)".
4. QuickPick: Claude Code, Codex.
5. Prompt string: Claude `/sustain-architecture <focus>`, Codex `$sustain-architecture <focus>` (no trailing space when focus is empty).
6. Look up `claude` / `codex` on the extension host's `PATH` (plus `PATHEXT` on Windows). Found → `window.createTerminal({ name: "Sustain: <Agent>", cwd: root, shellPath: <resolved binary>, shellArgs: [prompt] })` and show it. Passing the prompt as an argument, not via `sendText`, avoids shell quoting and `$` expansion.
7. Not found → warning "`<cli>` was not found on PATH." with a "Copy prompt" button that copies the prompt string.

AC: `[e2e]` with a stub `claude` script on a temp PATH, the created terminal's `creationOptions` carry the expected `shellPath`, `cwd` and `shellArgs`; missing CLI shows the warning; prompt formats unit-tested. `[e2e]` `[unit]`

### 7.7 Viewer

**FR-VIEW-01 Open command.** `Sustain: Open Architecture` (`sustain.openArchitecture`): folder choice, then load the newest candidate (FR-VIEW-02). None found → info "No architecture diagram yet." with a "Generate" button (runs FR-GEN-01). `Sustain: Open Architecture File…` (`sustain.openArchitectureFile`): QuickPick of all candidates in the folder, newest first, labelled by run folder and `meta.title`, plus "Browse…" (file dialog, `*.json`). The repo root for a browsed file outside `.archify/` is the chosen workspace folder. `[e2e]`

**FR-VIEW-02 Newest candidate.** Scan `<root>/.archify/*/candidate.json`. Folders matching `^architecture-.+-(\d{8}-\d{6})(-\d+)?$` sort by that timestamp, then by `-N`, descending; non-matching folders sort after all matching ones, by `candidate.json` mtime descending. AC: unit test with mixed names and mtimes. `[unit]`

**FR-VIEW-03 Tolerant parse** (`tolerant.ts`, browser-safe, no schema validation):

- Unparseable JSON, a non-object root, or no non-empty `components` array → error notification "Can't show `<file>`: <reason>", panel shows an empty state with the same text.
- Components without a string `id` are skipped; duplicates after the first are skipped; missing `label` → use `id`; unknown `type` → `external` styling.
- Connections whose `from`/`to` don't resolve are skipped. Boundary `wraps` entries that don't resolve are dropped; a boundary left with no members is skipped.
- `sources` entries without a string `path` are skipped.

AC: unit test per rule; all 24 fixtures parse with no skips. `[unit]`

**FR-VIEW-04 Panel.** One `WebviewPanel` (viewType `sustain.architecture`) per window; re-running the command reveals and reloads it. Title `Architecture: <meta.title>`. Opens in `ViewColumn.Active` when no editor is open, else `ViewColumn.Beside`. `retainContextWhenHidden: false`; the host re-sends the document when the panel becomes visible. Host → webview: `{type: "load", doc, file}`, `{type: "empty", message}`. Webview → host: `{type: "ready"}`, `{type: "openSource", componentId, index}`. `[e2e]`

**FR-LAY-01 Mode.** Authored mode when every kept component has an authored rect: `pos`, or `row`+`col` when root `layout.mode == "grid"`, converted as `origin + (col·(cellW+gapX), row·(cellH+gapY))` with Archify defaults `origin [40,80]`, `cols 4`, `gapX 30`, `gapY 40`, `cellW 130`, `cellH 64`; `pos` wins over a cell; `size` default 120×60. Otherwise auto mode; partial positions are ignored. AC: port the prototype's `archify_repo_grid_fixture_resolves_to_expected_positions` expectations. `[unit]`

**FR-LAY-02 Auto layout.** elkjs `layered`, `edgeRouting: ORTHOGONAL`, `hierarchyHandling: INCLUDE_CHILDREN`, `spacing.nodeNode: 60`, `layered.spacing.nodeNodeBetweenLayers: 110`, `spacing.edgeNode: 20`. Node size: measured label/sublabel/tag lines plus padding, at least 120×60 (the measurer is injected: canvas `measureText` in the webview, fixed advance in tests). Run both `direction: RIGHT` and `DOWN`; keep the one whose fit-to-viewport scale (viewport = current panel size, 1600×1000 in tests) is larger; ties pick `RIGHT`. AC: every fixture lays out; no two component boxes overlap; deterministic output for the same input. `[unit]`

**FR-LAY-03 Boundaries.** Nesting by member sets: process boundaries in document order; a boundary is placed in the ELK hierarchy if its member set is disjoint from or strictly contains/is contained by every already-placed boundary; its parent is the smallest placed strict superset; each component's parent is the smallest placed boundary containing it. A boundary that partially overlaps or equals a placed one is not placed in the hierarchy; after layout it is drawn as a rectangle around its members' boxes with 16 px padding, not nesting anything. In authored mode every boundary is drawn that way (rectangle around members, 30 px sides, 50 px bottom for the label, matching the prototype). AC: nested fixture puts children inside parents; overlapping-boundary test produces both rectangles, neither nested. `[unit]`

**FR-LAY-04 Edges.** Auto mode: ELK's orthogonal sections. Authored mode: a straight segment between the two boxes' centres, clipped to each box's border. Self-loops: a small rectangle off the node's right side. Authored edge geometry (`via`, sides, `route`, label offsets) is ignored. Label anchor: midpoint of the longest segment. `[unit]`

**FR-VIEW-05 Rendering.** SVG, colours from VS Code theme CSS variables only:

| `type` | Colour variable |
|---|---|
| frontend | `--vscode-charts-blue` |
| backend | `--vscode-charts-green` |
| database | `--vscode-charts-purple` |
| cloud | `--vscode-charts-yellow` |
| security | `--vscode-charts-red` |
| messagebus | `--vscode-charts-orange` |
| external | `--vscode-descriptionForeground` |

Node: rounded rect, 1.5 px stroke in the type colour, fill = type colour at 12 % opacity, `label` (bold), `sublabel`, `tag` badge. Boundaries: dashed stroke `--vscode-panel-border`, label top-left; `security-group` uses `--vscode-charts-red`. Connections: arrowhead at `to`; `default` `--vscode-foreground` 1.25 px; `emphasis` `--vscode-focusBorder` 2.5 px; `security` `--vscode-charts-red` 1.5 px; `dashed` dasharray `6 4`. Labels on a `--vscode-editor-background` halo. Font `--vscode-font-family`. Ignored: `icon`, `brand`, `cards`, `legend`, `views`. AC: `[dom]` test renders a fixture and asserts element counts and classes per type/variant; theme switching `[manual]`.

**FR-VIEW-06 Viewport.** Fit to view on load. Drag on empty canvas pans; wheel/trackpad scroll pans; Ctrl/⌘ + wheel and pinch zoom around the pointer; zoom range 10–400 %. Toolbar: Fit, −, +, 100 %. Keys when the webview is focused: `+`/`=`, `-`, `0` (100 %), `f` (fit). On reload of the same file (FR-WAT-01) the viewport is kept; on a different file it fits. `[dom]` for the math (zoom clamps, zoom-around-point), `[manual]` for feel.

**FR-VIEW-07 Tooltip.** Hovering a node 300 ms shows a tooltip: label, sublabel, type, and every source as `path:line–end_line` (or `path:line`, or `path`) with its `label`. The tooltip stays while the pointer is over the node or the tooltip and hides 200 ms after leaving both. Clicking a source entry posts `openSource` with that index. `[dom]`

### 7.8 Navigation

**FR-NAV-01 Click.** Clicking a node posts `{type: "openSource", componentId, index: 0}`. When the component has no sources, the host shows a status-bar message "`<label>` has no source references" for 3 s and opens nothing. Click vs drag: pointer movement under 4 px counts as a click. `[dom]` for the posted message and the click/drag threshold, `[e2e]` for the no-sources status message.

**FR-NAV-02 Open.** The host resolves `sources[index]` against the repo root and opens it with `showTextDocument` in a column different from the panel (`panel.viewColumn === 1 ? 2 : 1`, `preserveFocus: false`):

- `line` and `end_line`: select lines `line..end_line` (whole lines), reveal `InCenterIfOutsideViewport`.
- `line` only: select that line.
- Neither: open at the top, no selection.
- Highlight the selected lines with a whole-line decoration using `editor.rangeHighlightBackground` for 2 s.

AC: `[e2e]` sends `openSource` through the panel's message handler (test hook, FR-TEST-01) for a fixture repo and asserts the active editor's document path, selection and view column.

**FR-NAV-03 Stale references.** Checked on click, never on load:

- Path that would resolve outside the repo root (absolute, `..`, backslashes) → error "Invalid source path: `<path>`", nothing opens.
- Missing or not a regular file → error "Stale reference: `<path>` no longer exists", nothing opens.
- `line` or `end_line` beyond the file's line count → error "Stale reference: `<path>` has N lines; the diagram cites L–E", the file opens with no selection.
- Lines that moved within range are not detected.

The same rules apply to tooltip entries. AC: `[e2e]` one case per rule.

### 7.9 Watching

**FR-WAT-01 Watch.** A `FileSystemWatcher` on `<root>/.archify/*/candidate.json` for every workspace folder.

- Change to the file the panel shows → re-send it (viewport kept).
- A new candidate that is now the newest for its folder → if the panel is open for that folder, load it; otherwise info notification "New architecture diagram: `<run folder>`" with "Open".
- The panel's file deleted → panel shows the empty state "This diagram was deleted."
- Events are debounced 300 ms.

AC: `[e2e]` create and modify a candidate in a temp workspace and assert panel loads (via test hook).

**FR-LIVE-01 Claude Code.** In an Extension Development Host opened on `reference/sustain-prototype`: Install Agent Skills → Generate Architecture (Claude Code, empty focus) → the run finishes with `accepted` within 3 repairs → the viewer offers/opens the diagram → clicking 3 different nodes opens the cited ranges. **FR-PKG-01 Package.** `npm run package` produces `sustain-<version>.vsix` with `@vscode/vsce`; installing it into a clean VS Code profile runs all four commands. `[manual]`

**FR-DOC-01 README.** Install from `.vsix`, the four commands, the skill workflow for both agents, Node ≥ 18 requirement, what's in `.archify/`. `[manual]`

**FR-DOC-02 Architecture document.** `docs/architecture.md` describes the system as built, not as planned: purpose in two sentences; a component diagram (mermaid) of extension host, webview, `src/model`, `src/layout`, the skill scripts and the external agent; module responsibilities and allowed dependency directions (matching NFR-QUAL-03); the three main flows as mermaid sequence diagrams (generate → validate → publish, open → layout → render, click → resolve → open/stale); the webview message protocol; on-disk layout (`.archify/`, `.agents/skills/`, `.claude/skills/`, `dist/`); trust boundaries (webview CSP, no network, deny-list, repo-root confinement); links to the ADRs behind each part. AC: at the end of every milestone it matches the code (module names, message types, file paths exist); checked in the milestone review. `[manual]`

**FR-DOC-03 Architecture decision records.** `docs/adr/` uses MADR 4.0 (https://adr.github.io/madr/):

- `template.md` is the MADR 4.0 template. Each ADR is `NNNN-<kebab-case-title>.md`, numbered from `0001` without gaps, never renumbered.
- YAML front matter: `status` (`proposed`, `accepted`, `rejected`, `deprecated`, or `superseded by [ADR-NNNN](NNNN-....md)`), `date` (YYYY-MM-DD), `decision-makers`. Owner decisions list `owner`; implementer decisions list `implementer` and use status `accepted` unless they need owner approval (§10), in which case `proposed` until the owner answers.
- Required sections: `# <title>`, `## Context and Problem Statement`, `## Considered Options` (at least two), `## Decision Outcome` (`Chosen option: "…", because …`) with `### Consequences` (`Good, because …` / `Bad, because …`). Use `## Decision Drivers`, `### Confirmation` (point at the tests or checks that enforce it), `## Pros and Cons of the Options` and `## More Information` when they add information.
- `README.md` is the index: a table of number, title, status, date for every ADR file.
- Accepted ADRs are not edited except to change `status`. A changed decision gets a new ADR; the old one becomes `superseded by …`.
- **What needs an ADR:** every §5 decision (seeded in M0, `0001` being "Record architecture decisions with MADR"); every decision §10 lets the implementer make that changes structure, a dependency, a file format, a user-visible behaviour detail not fixed by §7, or a cross-module interface; every deviation from a prototype behaviour named in a "port of" requirement; every fallback taken from §12. Not needed for naming, refactors inside one module, or test-only structure.
- Implementer-made decisions already known when this spec was written get ADRs when their milestone is implemented: straight clipped edges in authored mode and overlay rectangles for overlapping boundaries (FR-LAY-03/04, M3); auto direction choice (FR-LAY-02, M3); theme colour mapping (FR-VIEW-05, M3); `repo-facts.mjs` creating the run folder (FR-RF-01, M1); terminal launch via `shellPath`/`shellArgs` (FR-GEN-01, M2); validator output contract and exit codes (FR-VAL-01, M1); the `activate()` test hook and `happy-dom` DOM tests (FR-TEST-01, M4).

AC: `npm run check:docs` (part of `npm run check`) verifies every `docs/adr/NNNN-*.md` has the front matter fields and required sections, numbers are contiguous, the index lists every file with matching status, and every relative link in `docs/**/*.md` resolves. Content quality: `[manual]` in the milestone review. `[unit]` `[manual]`

## 9. Process

- **Resume protocol.** At the start of every session, read this spec, `docs/progress.md`, `docs/architecture.md` and the `docs/adr/README.md` index, then continue from the first unticked item of the earliest unfinished milestone.
- **progress.md** holds a milestone status table, one checklist per milestone with every requirement ID, and a log. Tick an item only when its AC passes, and write the evidence next to it: test names, commands run and their results.
- **Decisions as they happen.** Write the ADR (FR-DOC-03) in the same change that implements the decision, not at the end of the milestone. Reference ADR numbers from code comments only where the code would otherwise look wrong.
- **End of milestone.** NFR-QUAL-01 gates green; `docs/architecture.md` updated to match the code (FR-DOC-02); every decision made in the milestone has an ADR and the index is current; `progress.md` updated, its log line naming the ADRs added; one local commit with message `M<n>: <title> (<requirement IDs>; ADR <numbers>)`. Never push. The repo has no commits yet; M0 makes the first.
- **Porting rule.** When a requirement says "port of", read the cited prototype file and reproduce its behaviour and test cases; a deliberate difference gets an ADR (FR-DOC-03).
- **Prerequisites the implementer may lack.** VS Code is not installed on the build machine: `@vscode/test-electron` downloads its own copy for `[e2e]`. `[manual]` and `[live]` items need the owner (VS Code or Cursor, `claude`, `codex` on PATH); when they are the only open items, stop and hand them over with exact steps instead of skipping them.

## 10. Deviation policy

- The implementer may make implementation-level decisions (internal module split, algorithms, an ELK option value, test structure). Decisions meeting FR-DOC-03's "what needs an ADR" rule get an accepted ADR with `decision-makers: implementer` and the evidence in `## More Information`; smaller ones are noted in the progress log.
- The implementer must stop and ask the owner before changing: goals, non-goals or anything in §5 (or the ADRs seeded from it); user-visible behaviour, command names, messages or file locations in §7; the dependency list beyond NFR-QUAL-02's rules; anything that would send data off the machine. While waiting, write the ADR with status `proposed` and continue with work that doesn't depend on it.

## 11. Definition of done

- Every AC in §7 passes with evidence in `progress.md`.
- `npm run check` (including `check:docs`) and `npm run test:e2e` are green.
- `docs/architecture.md` matches the shipped code; every ADR is `accepted`, `rejected`, `deprecated` or `superseded` (none left `proposed`).
- FR-LIVE-01 and FR-LIVE-02 recorded.
- The owner's `[manual]` checks are complete.
- The `.vsix` installs and works in a clean profile.
