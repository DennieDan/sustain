# Build, test and docs-check harness

## Context and Problem Statement

M0 needs working gates (NFR-QUAL-01) before any feature exists: a build that grows target by target, unit and DOM test projects, an `[e2e]` suite inside a downloaded VS Code, and a docs checker (FR-DOC-03). Spec §6 fixes the top-level files but not where the e2e build output and the docs checker live, nor how the e2e suite gets mocha types without a dependency outside NFR-QUAL-02.

## Decision Drivers

* Only the dependencies of NFR-QUAL-02; extra dev dependencies need a justification.
* Reproducible e2e runs on a machine without VS Code.
* Nothing test-only may end up in `dist/` (it ships in the `.vsix`).

## Considered Options

* esbuild-compiled e2e suite in `out/e2e/`, VS Code version pinned in `test/e2e/runTest.ts`, local typings for the mocha API used, dependency-free `scripts/check-docs.mjs`
* `tsc`-emitted e2e suite with `@types/mocha` and `@vscode/test-cli`, docs checker as a vitest-only test
* e2e suite built into `dist/test/`

## Decision Outcome

Chosen option: "esbuild-compiled e2e suite in `out/e2e/`, VS Code version pinned, local mocha typings, dependency-free `scripts/check-docs.mjs`", because it uses only the listed dependencies, keeps test code out of `dist/`, and makes `npm run check:docs` a plain Node command that the unit tests can also import.

* `esbuild.mjs` builds `dist/` (extension, webview, skill files and script bundles as each milestone adds them); `node esbuild.mjs --e2e` bundles `test/e2e/runTest.ts` and `test/e2e/suite/*.ts` to `out/e2e/` (gitignored, excluded by `.vscodeignore`).
* `test/e2e/runTest.ts` pins two VS Code versions and runs every scenario on each: `1.126.0`, the lowest supported version, and `1.141.0`, the latest stable; `engines.vscode` is `^1.126.0`. M0 pinned `1.141.0`, the stable release at the time; it was lowered on 2026-10-11 so that Devin Desktop (VS Code 1.126.0) and Cursor (VS Code 1.128.0) can install the `.vsix`.
* `test/e2e/mocha.d.ts` declares only the programmatic `Mocha` API used by `suite/index.ts`; `test/e2e/tdd.ts` re-exports the TDD globals with types so they do not leak into the vitest type scope.
* `vitest.config.ts` defines two projects: `unit` (Node, `test/unit/**`) and `dom` (happy-dom, `test/dom/**`).
* `scripts/check-docs.mjs` is plain ESM with JSDoc types, type-checked by `tsc` through `checkJs`.

### Consequences

* Good, because no dependency beyond NFR-QUAL-02 was added.
* Good, because e2e results are reproducible against a known VS Code build.
* Bad, because the local mocha typings must be extended by hand if the suite uses more of mocha's API.
* Bad, because the pinned VS Code version must be bumped deliberately (with `engines.vscode`).

### Confirmation

`npm run check` and `npm run test:e2e` pass (evidence in `docs/progress.md`, M0); `test/unit/checkDocs.test.ts` covers the docs checker.

## Pros and Cons of the Options

### esbuild e2e in `out/`, pinned VS Code, local typings, `scripts/check-docs.mjs`

* Good, because it reuses the existing bundler and needs no new packages.
* Neutral, because it adds two folders (`scripts/`, `out/`) not listed in spec §6.
* Bad, because hand-written typings can drift from mocha.

### `tsc` e2e, `@types/mocha`, `@vscode/test-cli`

* Good, because it is the template generated by `yo code`.
* Bad, because it adds two dev dependencies outside NFR-QUAL-02.

### e2e built into `dist/test/`

* Good, because there is a single output folder.
* Bad, because `.vscodeignore` ships `dist/**`, so tests would be packaged.

## More Information

Evidence: `npm run test:e2e` downloaded VS Code 1.141.0 (darwin-arm64) and passed the smoke suite (3 tests) on 2026-10-10. Mocha 12 is ESM internally and loaded by `require` inside the extension host, which works on the host's Node.
